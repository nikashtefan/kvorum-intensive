Инструменты · Cursor

Cursor — редактор кода с AI внутри

Что такое VS Code?

VS Code — это популярный текстовый редактор для кода от Microsoft. Большинство разработчиков пишут код именно в нём. Cursor — это VS Code, только с встроенным AI. Выглядит точно так же.

  • Устанавливается как обычная программа
  • Работаешь с реальными файлами и папками проекта
  • AI видит весь контекст — понимает связи между файлами
  • Composer: описываешь задачу → он меняет нужные файлы сразу
Пример — добавить форму

«Добавь форму обратной связи с проверкой email» → Cursor находит нужные файлы и меняет их все сразу

Когда брать Cursor

Полноценный проект с логикой, базой данных, несколькими страницами — там где нужен полный контроль

Когда брать Bolt

Быстро проверить идею, сделать лендинг или прототип — там где важна скорость

Инструменты · Bolt / Replit

Bolt и Replit — быстрый старт в браузере

Bolt.new
  • Открываешь в браузере — ничего не устанавливаешь
  • Вводишь задачу → получаешь работающий сайт за 2–5 минут
  • Хороший UI из коробки, сразу красиво
  • Мгновенный деплой на публичный URL
  • Растёт по токенам — на больших проектах дорожает
Replit
  • Гибче — подходит для любого языка
  • Хорош для ботов и бэкенд-логики
  • Встроенный хостинг — не нужен Vercel
  • AI-агент сам пишет и запускает код
  • Бесплатный tier ограничен по мощности

Стратегия: начинаешь в Bolt для скорости → когда проект вырос, переносишь в Cursor для контроля

Термин

Что такое PRD

PRD (Product Requirements Document) — короткое описание того, что ты хочешь построить. Не нужен большой формальный документ — достаточно ответов на несколько вопросов.

  • Для кого этот продукт?
  • Какую задачу он решает?
  • Что должен уметь — список функций
  • Как выглядит успешный результат?
  • Что точно не нужно в первой версии?
Зачем нужен PRD

Когда даёшь AI чёткий контекст — он строит именно то что нужно. Без PRD получаешь «что-то похожее».

Как сделать PRD

Открываешь Claude и пишешь: «Помоги мне написать PRD для [идея]. Задай мне вопросы.» Он сделает всё сам.

Принципы работы с LLM

Промптинг — это прошлый этап

Раньше учились писать «идеальные промпты» — потому что модели были слабые. Сейчас модели умнее. Ты просто ставишь задачу.
Раньше — промпт-инжиниринг

«Действуй как эксперт в области Х. Используй формат Y. Дай 5 вариантов с плюсами и минусами...»

Сейчас — просто задача

«Мне нужен лендинг для B2B-сервиса доставки. Аудитория — рестораны. Хочу форму для заявки и блок с ценами.»

Принципы работы с LLM

Ты — менеджер. LLM — исполнитель.

  • Давай контекст — что за проект, для кого, зачем
  • Формулируй цель — что должно получиться на выходе
  • Называй ограничения — стек, стиль, что нельзя
  • Итерируй — первый результат обычно далёк от идеала, это нормально
  • Не знаешь что хочешь? Попроси LLM задать тебе вопросы
Плохая постановка

«Сделай мне сайт»

Нормальная постановка

«Я PM, делаю лендинг для B2B SaaS. Нужен хедер, описание продукта и форма для лида. Тёмная тема, минимализм.»

Принципы работы с LLM

Где выигрывают PM и предприниматели

Ключевая задача в работе с LLM — понимать какой результат ты хочешь получить. Это и есть продуктовое мышление.

  • Разработчики теперь становятся более продуктовыми — умение поставить задачу важнее знания синтаксиса
  • Не знаешь как должен выглядеть результат? Попроси LLM: «найди лучшие практики, объясни образ результата»
  • Это базовый уровень. Продуктовые и бизнесовые навыки мультиплицируют эффект от AI
