# Библиотека шаблонов промптов

_Справочник · ≈ 6 мин_

## Как пользоваться

Шаблоны — это каркас, не финальный текст. Заполни заглушки в `[квадратных скобках]`, выбрось ненужные секции, добавь свои ограничения. Все шаблоны построены на принципах из core-1-brief.

## Универсальный бриф

```
КОНТЕКСТ
[Кто я. Для кого делаю. Какую боль решаю. 2-4 предложения.]

РОЛЬ
[Кем должен быть Claude. «Senior backend-инженер с опытом в...»,
«PM с опытом запуска B2C-продуктов», «UX-копирайтер для финтеха».]

ЗАДАЧА
[Одна задача. Если две — это два брифа.]

ОГРАНИЧЕНИЯ
- [Что нельзя]
- [Что обязательно]
- [Технологии / язык / тон / формат]

КРИТЕРИИ ПРИЁМКИ
- [Как пойму, что результат хороший]
- [Что должно работать]
- [Чего не должно быть]
```

## Промпт на план (перед кодом)

```
Прежде чем писать код, дай план:

1. Какие файлы будут изменены и что именно в них поменяется
2. Какие новые файлы появятся
3. Какие зависимости подтянутся (если будут)
4. Возможные риски и побочные эффекты
5. Что НЕ входит в эту задачу (что мы намеренно не делаем)

Не пиши код, пока я не подтвержу план.
```

## Промпт «опиши перед изменением»

```
Прежде чем менять что-либо, опиши:
1. Какие файлы участвуют в работе [фичи/модуля X]
2. Какие данные функция получает на вход
3. Что происходит при каждом значимом значении входа
4. Где модуль используется (вызовы из других мест)

Не пиши код. Только описание.
```

## Промпт на ревью своего кода

```
Запусти суб-агента в роли code-reviewer.
Задача: посмотри на [функцию / файл / диапазон строк],
найди минимум 3 потенциальные проблемы — баги, неэффективности,
плохие практики. Не правь, только зарепорти.

Контекст: см. CLAUDE.md.
Стиль ревью: конкретные строки, конкретные проблемы.
Без общих советов «лучше использовать X».
```

## Промпт на отладку

```
Баг: [короткое описание]

Воспроизведение:
1. [шаг]
2. [шаг]
3. [что вижу]

Ожидаемое: [что должно было произойти]

Точный текст ошибки:
```
[копипаст]
```

Файлы, которые я недавно менял: [...]

Сначала сформулируй гипотезу о причине. Не правь, пока я не подтвержу.
```

## Промпт на рефакторинг

```
Зарефактори [функцию/модуль X] в файле [Y].

Цель рефакторинга: [читаемость / переиспользование / производительность]
Что НЕ должно поменяться: поведение (вход → выход).
Что НЕ должно поменяться: публичный API (имя, сигнатура).

План рефакторинга:
1. [первый шаг — самый маленький]
2. [...]

Делай по одному шагу. После каждого жди подтверждения.
```

## Промпт на саммари интервью

```
Сделай саммари этого интервью по структуре:

1. Кто (роль, контекст) — 2-3 строки
2. JTBD: ситуация → мотивация → ожидаемый результат
3. Боли и обходные пути — буллетами
4. Критерии выбора — буллетами
5. Цитаты-самородки (3-5 дословных, с указанием темы)
6. Противоречия и пробелы

Не выдумывай. Если в интервью этого не было — пропусти секцию.
Цитата важнее пересказа.
```

## Промпт на черновик PRD

```
Сделай черновик PRD для [фича / продукт].

Структура:
- Контекст и проблема
- Целевой пользователь и его JTBD
- Метрика успеха (одна главная)
- Что входит в MVP (минимально жизнеспособную версию)
- Что НЕ входит (явный список «вне задачи»)
- Риски и допущения
- Зависимости

Источники, которые я приложил: [...]
Длина: [N страниц / N слов].
Тон: [сухой / разговорный].
```

## Промпт на разбор данных

```
Контекст: [что за данные, откуда, что значат поля]

Задача: ответь на вопрос — [конкретный вопрос].

Формат ответа:
- Главный ответ — одной фразой
- Цифры с округлением до [N]
- Источник каждой цифры (какие строки/поля считал)
- Что в данных вызвало сомнение (если что-то)

Не делай выводов вне данных. Не предлагай рекомендаций.
```

## Промпт на текст для лендинга

```
КОНТЕКСТ
[Продукт / услуга. Кто покупатель. Что у конкурентов.]

РОЛЬ
Копирайтер с опытом в [нише].

ЗАДАЧА
Напиши тексты для лендинга по блокам: hero, проблема,
решение, как это работает (3 шага), CTA.

ОГРАНИЧЕНИЯ
- Тон: [сухой / тёплый / провокационный]
- Не использовать: «революционный», «инновационный», «disruptive»,
  «мы команда профессионалов», «индивидуальный подход»
- Длина hero: 1 заголовок (≤8 слов) + 1 подзаголовок (≤20 слов)
- Целевое действие: [что должен сделать посетитель]

КРИТЕРИИ ПРИЁМКИ
- Hero понятен за 5 секунд
- Каждый блок отвечает на возражение, а не «продаёт»
- Нет общих фраз
```

## Промпт на CLAUDE.md из существующего проекта

```
Прочитай структуру этого проекта. Сгенерируй CLAUDE.md по шаблону:

# Проект: [название из package.json / README]

## Что это
[Из README или комментариев в коде]

## Стек
[Из package.json / requirements.txt / pyproject.toml — с версиями]

## Структура
[Папки с назначением — по одной строке]

## Соглашения
[Что заметил в коде — именования, паттерны]

## Антипаттерны
[Что выглядит как «так точно не делаем»]

## Текущий фокус
[Оставь заглушку — заполню сам]

Не выдумывай. Если что-то непонятно из кода — помечай "TODO: уточнить".
```
