# Мини-проект пошагово

_Практика · ≈ 12 мин_

## Зачем этот блок

Все предыдущие блоки — про принципы. Этот — про результат. Ты выходишь с интенсива не с конспектом, а с рабочим артефактом, который можно показать.

Три трека на выбор. Выбираешь до второго дня.

## Трек A — Продакт

**Целевой артефакт:** внутренний инструмент для своей работы.

Варианты:
- Дашборд: загружаешь CSV с метриками — видишь воронку, когорты, изменения
- Тренажёр интервью: задаёт вопросы по гайду, ты отвечаешь, получаешь обратную связь
- Генератор отчётов: на вход данные, на выход — структурированный документ для руководства или заказчика

**Стек:** Claude Code + локальный HTML/JS либо Next.js. Опционально — MCP к Notion/Drive.

**Минимум на выходе:**
- Локально работающий артефакт
- README с инструкцией «как запустить»
- Один реальный кейс использования (на твоих данных)

**Что обсудим на сборке:** бриф под этот артефакт, CLAUDE.md проекта, какие skills заложить, как избежать галлюцинаций при работе с твоими данными.

## Трек B — Предприниматель

**Целевой артефакт:** одностраничник-MVP (минимально жизнеспособный продукт) с минимальной функциональностью.

Варианты:
- Лендинг + форма заявки + сбор заявок в базу
- Калькулятор стоимости услуг + отправка результата на почту
- Простая запись на услугу: выбор времени → имя → подтверждение

**Стек:** Claude Code + Next.js + Supabase, либо без серверной части через Tally / Formspree.

**Минимум на выходе:**
- Задеплоенный URL (Vercel)
- Форма работает, данные сохраняются (или приходят на почту)
- Вёрстка подстраивается под мобильный

**Что обсудим на сборке:** чем твой будет отличаться от тёзки-конкурента, структура одностраничника с конверсией, как НЕ делать «безликий AI-лендинг», базовое SEO + Open Graph (превью при шаринге в мессенджеры и соцсети).

## Трек C — Маркетолог

**Целевой артефакт:** интерактивный инструмент для сбора заявок (лидген).

Варианты:
- Квиз: подбор продукта/услуги по 5–7 вопросам, выдача результата
- Калькулятор: «сколько вы экономите/теряете», на выходе персональная цифра
- AI-помощник: вводишь свою ситуацию — получаешь персональную рекомендацию (на базе языковой модели)

**Стек:** Claude Code + Next.js / простой HTML, по желанию Anthropic API для AI-варианта.

**Минимум на выходе:**
- Задеплоенный URL
- Прохождение квиза/калькулятора 1–2 минуты
- Результат отправляется на почту/телеграм или сохраняется

**Что обсудим:** логика конверсии в квизах, AI-помощник без галлюцинаций, защита API-ключей, два варианта результата для сравнения по эффективности (A/B-тест).

## Пошаговый план сборки

### Шаг 1. Бриф проекта (15 минут)

Сядь с шаблоном из core-1-brief и заполни:
- Контекст: для кого этот артефакт, какую боль решает
- Роль: кем должен быть Claude в этой задаче (full-stack, frontend, копирайтер)
- Задача: одна, не три
- Ограничения: стек, дизайн, скоп
- Критерии приёмки: что значит «готово»

Сохрани бриф в файл `BRIEF.md` в папке проекта.

### Шаг 2. CLAUDE.md (10 минут)

В корне проекта создай CLAUDE.md по шаблону из core-2-claude-md. Минимум:
- Что это
- Стек с версиями
- Структура папок
- 3 соглашения
- 2 антипаттерна
- Текущий фокус

### Шаг 3. План архитектуры (20 минут)

Запусти Claude Code в plan mode (режим планирования: Shift+Tab). Дай BRIEF.md и попроси:
- Описать архитектуру
- Перечислить файлы, которые появятся
- Указать зависимости
- Выделить этапы (не более 5)

Прочитай. Уточни. Только после этого — кодирование.

### Шаг 4. Этап 1 — каркас (40–60 минут)

Самый минимальный работающий вариант: одна страница, одна форма, одна кнопка. Без стилей, без валидации, без красоты.

Цель: чтобы запускалось и проходился целевой сценарий.

После этапа: коммит «этап 1: рабочий каркас».

### Шаг 5. Этап 2 — наполнение (1–2 часа)

Добавляй фичи по одной. Каждую — через цикл план → код → верификация (см. core-4-workflow).

После каждой фичи: коммит. Сломаешь — откатишься на одну фичу, не на всё.

### Шаг 6. Этап 3 — деплой (30 минут)

Vercel, Netlify, Cloudflare Pages — выбирай по треку. Claude знает, как задеплоить — спроси.

Проверь:
- URL работает
- Целевой сценарий проходится на проде
- На мобильном открывается без горизонтального скролла

### Шаг 7. Подготовка демо (30 минут)

За 30 минут до окончания — стоп новым фичам. Только полировка и подготовка демо.

Подготовь:
- Один абзац: что это и для кого
- Один сценарий, который проходится за 1–2 минуты
- Скриншот или короткое видео для шаринга

## Общие правила сборки

1. **Один артефакт, не три.** Соблазн сделать «лендинг + бот + дашборд» — отказать. Собираем один, доводим до рабочего состояния.
2. **Меньше объём задачи — больше шанс закончить.** Если выбрал лендинг с 5 экранами — сначала 1 экран и форма, потом остальное.
3. **Промежуточный коммит после каждого такта цикла.** Сделал план — закоммитил «план». Сделал верификацию — закоммитил рабочую версию.
4. **Демо — не «ещё одна фича».** Полировка важнее.

## Продвинутый паттерн: AI внутри артефакта («Claude в Claude»)

В треках выше у части артефактов AI стоит **внутри** — это квиз с персональным результатом, AI-помощник, генератор отчётов. Технически это работает так: твой артефакт сам обращается к Claude через **Anthropic API**. То есть у тебя есть приложение, и в этом приложении есть AI-функция — она вызывает Claude из кода.

Простыми словами: Claude помогает тебе **сделать приложение**, и в это же приложение ты **встраиваешь Claude** для работы с пользователем. Один раз AI работает на тебя как инструмент сборки. Второй раз — как фича продукта. За один вечер ты можешь сделать AI-сервис без бэкенда — это и есть «Claude в Claude».

**Как это выглядит на практике** (пример: квиз-помощник для лидген-страницы маркетолога):

1. Пишешь в Claude Code один промпт: «Сделай страницу с формой — пользователь описывает свою ситуацию. На сабмите отправь введённое в Anthropic API с системным промптом "ты карьерный консультант, отвечай только на вопросы по теме X, в формате 3 пункта". Покажи ответ пользователю». Получаешь рабочий каркас за один заход — без бэкенда.
2. Идёшь на `console.anthropic.com`, заводишь API-ключ.
3. Кладёшь ключ в **переменные окружения хостинга** (Vercel/Netlify), не в код.
4. Деплоишь. Готово — у тебя AI-сервис, который работает на твоём API-ключе.

**Что обязательно проверить, прежде чем выкладывать в публичный доступ:**

- **Ключ — в переменные окружения, не в код.** Если он попадёт в публичный репозиторий — за ночь спишут все деньги с привязанной карты. Реальные истории есть.
- **Поставь лимит расхода в личном кабинете Anthropic.** На старте — $10–20 в месяц. Иначе бот, который пройдёт твою форму 1000 раз, нагенерит счёт. Лимит — твоя страховка от этого.
- **В системном промпте API-вызова жёстко ограничь тему.** Пример: «отвечай только на вопросы про подбор обучения по программированию. На остальное — "это вне моей компетенции, опишите задачу подробнее"». Иначе твой карьерный консультант начнёт рассказывать рецепты борща, а ты будешь за это платить.

**Когда AI внутри не нужен:**

Если артефакт — это лендинг, калькулятор по формуле, дашборд без персональных текстов от модели — встроенный API избыточен. Достаточно того, что Claude помог собрать сам артефакт. Anthropic API имеет смысл, когда **на каждое нажатие кнопки пользователю нужен персональный текстовый ответ**.

## Чек-лист готовности

- [ ] Артефакт открывается одной ссылкой / одной командой
- [ ] Целевой сценарий проходится за 1–2 минуты без подсказок
- [ ] README или короткое описание «что это и для кого»
- [ ] Могу за 2 минуты рассказать боль, которую решает
- [ ] Могу за 1 минуту показать «как сделано» (CLAUDE.md, ключевые промпты)
