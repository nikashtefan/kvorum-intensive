# CLAUDE.md — память проекта

_Основа · ≈ 12 мин_

## Зачем этот блок

Главная боль начинающих: «Claude всё забывает». Запустил новый чат — он не помнит, что вчера обсуждали. Открыл проект через неделю — не помнит, какой стек.

Это не баг. У Claude нет памяти между сессиями — есть только контекстное окно текущего разговора.

Решение — файл `CLAUDE.md` в корне проекта. Это конституция проекта. Claude автоматически читает её каждый раз, когда работает в этой папке. Один файл — и больше не нужно заново объяснять «у нас Next.js 14, Supabase, BEM, мы не используем `any`».

После этого блока ты перестанешь начинать каждую сессию с пересказа.

## Антипаттерн: объясняю заново каждый раз

Сценарий: собираешь админку. В понедельник настроил, объяснил стек, попросил таблицу студентов. Получил.

Закрыл. Во вторник открыл. Claude: «над каким проектом работаем?». Пересказываешь стек. Опять говоришь, что не любим `any`. 15 минут на восстановление контекста до первой полезной задачи.

Через неделю — час восстановления в неделю.

## Минимальная структура

```markdown
# Проект: Кворум LMS

## Что это
Админка для управления потоками интенсива по вайбкодингу.
Студенты видят свой прогресс, ведущие — прогресс группы.

## Стек
- Next.js 14 (app router)
- TypeScript (strict, без `any`)
- Supabase (auth + БД)
- Tailwind для стилей
- Деплой на Vercel

## Структура папок
- `/app` — роутинг и страницы
- `/components/ui` — переиспользуемые компоненты
- `/lib/supabase` — клиенты Supabase (server / client)
- `/lib/types.ts` — общие типы

## Соглашения
- Серверные компоненты по умолчанию
- Все запросы к БД — через server actions, не API routes
- Имена файлов — kebab-case (student-card.tsx)
- Имена компонентов — PascalCase (StudentCard)

## Как НЕ надо
- Не использовать `any` в TypeScript
- Не добавлять зависимости без согласования
- Не править схему БД напрямую — только через миграции

## Текущий фокус
Делаем экран roadmap для студента. Дизайн в /docs/roadmap.png.
```

Запустил Claude в этой папке — он сам прочитал. Не пересказываешь.

## Чем отличается от системного промпта

Системный промпт = правила для всех чатов с этим Claude.
CLAUDE.md = правила этого проекта.

Один человек работает над 5 проектами. У каждого свой CLAUDE.md. Не нужно держать в голове.

## Что класть, а что нет

**Класть:**
- Описание проекта (1–2 абзаца)
- Стек с версиями
- Структуру папок
- Соглашения о коде/тоне/именах
- Антипаттерны (что НЕ делать)
- Ссылки на ключевые файлы (схемы, дизайны, доки)
- Текущий фокус — над чем работаем сейчас

**Не класть:**
- Полную документацию (раздуёт контекст)
- Секреты, API-ключи, пароли (используй `.env`)
- Длинные истории «как мы пришли к этому решению»
- Всю переписку с командой


## Три слоя памяти

До этого мы говорили только про project CLAUDE.md — файл в корне конкретного проекта. На самом деле у Claude три слоя памяти, и разница между ними — критическая.

![Три слоя памяти Claude: user-global CLAUDE.md, project CLAUDE.md, auto-memory](/diagrams/memory-layers.svg)

### Слой 1. User-global CLAUDE.md

Лежит в `~/.claude/CLAUDE.md` (домашняя папка). Подгружается **во всех твоих сессиях, во всех проектах**. Сюда пишешь то, что верно про тебя в принципе:

- Кто ты (роль, опыт)
- Какой стиль ответов хочешь (язык, длина, без воды)
- Какие модели использовать на каких задачах
- Какие команды никогда не запускать без подтверждения

Это файл, который ты пишешь **один раз и поддерживаешь редко**. Без него Claude каждый раз начинает с нуля — не знает ни кто ты, ни как тебе отвечать.

### Слой 2. Project CLAUDE.md

То, про что был весь предыдущий раздел. Лежит в корне проекта. Подгружается только в этом проекте.

### Слой 3. Auto-memory — что Claude пишет сам

Самое недооценённое. Лежит в `~/.claude/projects/<id-проекта>/memory/`. Claude **сам ведёт** там заметки, когда узнаёт про тебя или проект что-то долговременное:

- «Юзер предпочитает Sonnet 4.6 для рутины, Opus только на сложном»
- «В этом проекте тестов нет — не предлагать их без явной просьбы»
- «Юзер просил не добавлять эмодзи никогда»
- «Дедлайн релиза мобилки 2026-03-05 — после этой даты не предлагать слияния»

Структура папки:
- `MEMORY.md` — индекс (короткие строки-ссылки на отдельные файлы)
- Отдельные `.md` файлы по темам, у каждого frontmatter с типом: `user` (про тебя), `feedback` (твои корректировки), `project` (контекст работы), `reference` (ссылки на внешние системы)

Claude читает индекс при старте сессии и подтягивает релевантные записи. Дописывает, когда замечает что-то важное и неочевидное.


## Что нужно сделать обязательно

На каждом новом проекте, и глобально один раз:

1. **Глобально, один раз:** создай `~/.claude/CLAUDE.md`. Минимум — кто ты, на каком языке отвечать, какие модели использовать, что НЕ делать без подтверждения. 30–50 строк.
2. **Глобально, один раз:** убедись, что есть папка `~/.claude/projects/` — Claude Code создаёт её сам при первом запуске.
3. **На каждом проекте:** создай `./CLAUDE.md` (тот, что разбирали выше).
4. **На каждом проекте:** не выключай auto-memory. По умолчанию она включена.
5. **Раз в месяц:** открой `MEMORY.md` индекс и пробеги глазами — устаревшие записи удали (например, если фича уже в проде, а Claude всё ещё помнит «делаем фичу X»).

## Лучшие практики

- **Глобальный CLAUDE.md держи коротким.** Длинный = шум во всех сессиях. Стек, инструменты — это в проектные.
- **Проектный CLAUDE.md обновляй каждую неделю** в разделе «текущий фокус». Остальное стабильно.
- **Auto-memory не редактируй руками** — пиши Claude словами «запомни, что...», он сам положит в правильное место с правильным типом.
- **Если Claude игнорирует правило, которое должен помнить** — проверь все три слоя по очереди: в каком из них правило записано, не противоречит ли другим, не устарело ли.
- **Никогда не клади в auto-memory секреты** — это обычные файлы на диске, в любой бэкап они попадут.
- **На общих/командных машинах** — auto-memory отключай или используй отдельный профиль. В ней копится твой личный контекст.

## CLAUDE.md для непрограммистов

Формат тот же, наполнение другое. Пример для папки с продуктовыми задачами:

```markdown
# Проект: Discovery Q2

## Что это
Папка с материалами по discovery новой фичи "командные дашборды".

## Контекст
- Я продакт в B2B SaaS
- Целевые юзеры — тимлиды команд 10-50 человек
- Идёт фаза кастдева, проведено 7 интервью

## Файлы здесь
- /interviews — расшифровки 7 интервью
- /docs/hypotheses.md — текущие гипотезы
- /docs/competitors.md — анализ конкурентов

## Как ты помогаешь
- Анализ интервью: ищешь паттерны, цитируешь дословно
- Помогаешь формулировать гипотезы по JTBD
- Готовишь материалы для презентаций — стиль сжатый

## Антипаттерны
- Не выдумывай инсайты, которых нет в данных
- Если в интервью противоречие — указывай оба варианта
- Не предлагай "решения" пока не закрыта фаза discovery
```

Claude теперь — твой ресёрч-аналитик, помнящий контекст работы.

## Projects + Knowledge Files — для тех, кто на claude.ai, а не на Code

В **claude.ai** в браузере есть аналог CLAUDE.md, только через интерфейс — это **Projects + Knowledge Files**.

- **Project** — папка чатов с общим фоном. Все чаты внутри одного Project делят один и тот же контекст.
- **Knowledge Files** — файлы, прикреплённые к Project один раз. Claude видит их в каждом новом чате этой папки — переприсылать не нужно.

То же самое, что CLAUDE.md, только не файл на диске, а настройка в веб-интерфейсе.

**Что прикрепить — рабочий минимум, 3 файла на проект:**

1. **Контекст продукта** — кто ты, для кого делаешь, на какой стадии. Аналог раздела «Что это» / «Контекст» из CLAUDE.md.
2. **Дизайн-система или стиль работы** — палитра, тон голоса, шаблоны отчётов. Чтобы Claude не выдавал «вообще красиво», а сразу в твоём стиле.
3. **Тулкит** — твои любимые инструменты, фреймворки, ссылки на документацию. Чтобы не предлагал чужие.

Один раз настроил Project — дальше каждый новый чат уже помнит, кто ты и что делаешь. Не собираешь контекст с нуля.
