# Инструменты Claude Code: skills, MCP, суб-агенты

_Основа · ≈ 13 мин_

## Зачем этот блок

Claude Code — это не один инструмент, а связка из трёх. Skills превращают разовые промпты в рычаги. MCP даёт доступ к внешним сервисам напрямую. Суб-агенты позволяют делегировать тяжёлые подзадачи без забивания основного контекста.

После этого блока ты понимаешь, какой инструмент применять к какой задаче — и где брать готовое, чтобы не писать с нуля.

## Контекст: общий ресурс, который эти три инструмента берегут

В одной сессии с Claude есть **контекстное окно** — суммарный объём текста, который модель видит и помнит «прямо сейчас». У Sonnet 4.6 это около 200 тысяч токенов, у Opus 4.7 — больше, но всё равно конечно. В контекст входит всё: твои сообщения, ответы Claude, прочитанные файлы, выводы команд, инструкции из CLAUDE.md.

Когда контекст забит — три симптома: ответы становятся медленнее, начинают дороже стоить (расход растёт нелинейно), и модель **забывает то, что было в начале** (эффект «потерян в середине» — то, что в самой середине окна, проседает первым).

Поэтому на длинной задаче без правильных инструментов сценарий всегда один: первые два часа всё хорошо, дальше Claude всё чаще «забывает» договорённости, начинает ломать ранее работавшие куски, и приходится открывать новый чат и пересказывать всё заново.

**Skills, MCP и суб-агенты решают одну общую проблему — каждый со своей стороны:**

| Инструмент | Что делает с контекстом | Простыми словами |
|---|---|---|
| **Skill** | Не лежит в контексте. Подгружается только когда триггер сработал. | Шаблон промпта живёт в файле, а не в каждом твоём сообщении |
| **MCP** | Подтягивает данные **по требованию**, а не сразу. | Не нужно копировать 50 страниц документации — Claude сходит и прочитает только нужный кусок |
| **Суб-агент** | Тяжёлая работа идёт в **отдельной сессии** с отдельным контекстом. Назад приходит короткое резюме. | Чтение 20 файлов или часовой ресёрч не засоряют твой основной чат |

То есть три инструмента — это не три не связанных штуки, а **три разные защиты твоего основного контекста**. Skills экономят на повторе инструкций, MCP — на копипасте данных, суб-агенты — на длинных «черновых» работах.


## Skills — свой склад промптов

Через две недели работы с Claude замечаешь: одни и те же промпты пишешь снова и снова. «Сделай саммари интервью». «Преобразуй CSV в дашборд». «Напиши PRD по нашему шаблону».

Skill — это файл с инструкцией, который Claude автоматически подхватывает, когда понимает «эта задача из моих скиллов». Один раз настроил — десять раз использовал без переписывания.

![Поток работы skill: триггер в description → чтение SKILL.md → исполнение по шагам](/diagrams/skills-flow.svg)

### Анатомия SKILL.md

```markdown
---
name: interview-summary
description: Используй этот skill, когда нужно сделать саммари
  пользовательского интервью. Триггеры — слова "саммари интервью",
  "разбери интервью", "выводы по интервью".
---

# Skill: Саммари пользовательского интервью

## Как исполнять

Шаг 1. Прочитай расшифровку целиком.
Шаг 2. Сформулируй ответы на 5 вопросов: кто, JTBD, боли, критерии,
       цитаты.
Шаг 3. Заверши блоком "противоречия и пробелы".

## Чего НЕ делай
- Не выдумывай. Если в интервью этого не было — не пиши.
- Не интерпретируй вместо респондента. Цитата важнее пересказа.
```

### Куда положить

Три места в Claude Code:
1. `.claude/skills/` в корне проекта — skill только для этого проекта
2. `~/.claude/skills/` в домашней папке — skill для всех проектов
3. Anthropic-managed skills — официальные, подключаются автоматически

### Откуда брать готовое — три маркетплейса

![github.com/anthropics/skills — официальный репозиторий Anthropic](/screens/marketplace-anthropic-skills.png)

1. **`github.com/anthropics/skills`** — официальный репозиторий Anthropic. Базовый набор для офисной работы: `pdf`, `docx`, `xlsx`, `pptx`, плюс мета-скиллы `skill-creator` и `mcp-builder`. Это первое место, куда стоит сходить.

2. **`github.com/obra/superpowers`** — самый популярный пользовательский набор. Ставится как плагин Claude Code одной командой. Внутри — готовые рабочие процессы (разработка через тесты, отладка, мозговой штурм), а не разовые шаблоны.

3. **`github.com/hesreallyhim/awesome-claude-code`** — собранный вручную список ссылок: skills, плагины, агенты, шаблоны. Если нужного готового нет в первых двух — почти всегда находится здесь.

### Топ-3 универсальных скилла

- **`skill-creator`** (Anthropic) — мета-скилл, который создаёт другие скиллы по диалогу. Самый ценный из всех: один раз ставишь, дальше делаешь свои не выходя из Claude.
- **`brainstorming`** (superpowers) — превращает размытую идею в техническое задание через серию правильных вопросов. Обязательно ставить продактам и предпринимателям.
- **`pdf`** (Anthropic) — извлекает таблицы и текст из PDF. Бесшовно работает с финотчётностью, выписками, договорами.

### Главное про skills

Skills — **очень индивидуальная история**. Готовые сборки покрывают 30% — остальное ты будешь делать под свой процесс. Не нужно ждать, пока кто-то напишет «правильный» скилл под твой кастдев или твой формат отчёта. Поставил `skill-creator` → описал свою задачу диалогом → получил рабочий SKILL.md за 5 минут.


## MCP — Claude с доступом к данным

До этого Claude был как умный коллега в изоляции — ты ему даёшь файлы, он работает. Чтобы посмотреть таблицу — копируешь и вставляешь. Чтобы записать результат — копируешь его ответ и руками создаёшь.

MCP (Model Context Protocol) убирает этот шов. Claude работает с внешними сервисами напрямую — открывает браузер, читает свежую доку, лезет в БД, отлаживает живую страницу.

![Claude как маршрутизатор запросов к разным MCP-серверам](/diagrams/mcp-routing.svg)

### Подключение

В Claude Desktop:
1. Settings → Connectors
2. Найди сервис, нажми Connect
3. Авторизуйся в браузере, разреши доступ

В Claude Code:
```bash
claude mcp add <имя-сервера>
```

### Откуда брать готовое — три маркетплейса

![mcp.so — крупнейший каталог MCP-серверов](/screens/marketplace-mcp-so.png)

1. **`modelcontextprotocol.io`** — официальный реестр и спецификация. Здесь смотришь, что вообще существует, и читаешь, как устроен протокол.

2. **`smithery.ai`** — устанавливается одной CLI-командой, без ручной правки конфигов. Самый удобный путь, если ты не хочешь возиться с JSON.

![smithery.ai — установка MCP через CLI](/screens/marketplace-smithery.png)

3. **`mcp.so`** — крупнейший каталог по количеству серверов (20K+). Поиск по сервисам, фильтры, рейтинги. Сюда идёшь, когда нужен MCP под конкретный нишевый инструмент.

### Топ универсальных MCP-серверов

- **Playwright MCP** (`github.com/microsoft/playwright-mcp`, официальный от Microsoft). Claude управляет браузером: открывает страницы, заполняет формы, делает скриншоты, парсит контент. Маркетологам — для разбора лендингов конкурентов; всем — для сбора данных, которые иначе нужно копировать руками.

- **Context7** (`github.com/upstash/context7`). Подтягивает свежую документацию любой библиотеки в контекст запроса. Решает главную причину галлюцинаций SDK — Claude больше не выдумывает методы, которых нет в актуальной версии.

- **Chrome DevTools MCP** (`github.com/ChromeDevTools/chrome-devtools-mcp`, официальный от Google). Claude видит реальный Chrome: консоль, network, performance. Незаменим для отладки задеплоенного лендинга или MVP, когда «у меня всё работает» не помогает.

- **Filesystem MCP** (`github.com/modelcontextprotocol/servers`, официальный). Даёт Claude прямой доступ к указанной папке на твоём компьютере: читать, искать, переименовывать, создавать. Полезен, когда работаешь не в Claude Code, а в Claude Desktop / claude.ai, и нужно подтянуть локальные файлы без копипаста. Сужай папку — давай доступ только к рабочей директории, не ко всему диску.

- **GitHub MCP** (`github.com/github/github-mcp-server`, официальный). Claude видит твои репозитории, issues, pull requests. Может создавать ветки, открывать PR, оставлять комментарии. Удобно для рутины: «посмотри открытые баги в репо X, сгруппируй по приоритету» или «открой PR из текущей ветки с описанием изменений».

### Главное про MCP

MCP — тоже **сильно индивидуальная история**. Какие сервисы ты подключаешь — зависит от твоего стека: какой таск-трекер, какие доки, какая база данных. Поэтому здесь нет «правильного списка» — есть три универсальных, которые помогают всем (браузер, документация, отладка), и дальше ты добавляешь под свои сервисы из каталога.


## Суб-агенты для сложных задач

Один Claude в одном чате — это один контекст и одна голова. Когда задача большая, голова забивается, качество падает.

Суб-агент — не «второй Claude». Это инструмент, через который Claude вызывает отдельную сессию для конкретной части работы. Эта сессия не видит твой основной контекст, у неё узкая задача и чистая голова. Закончила — вернула короткий отчёт.

![Делегирование суб-агенту: задача → отдельная сессия → короткий отчёт обратно](/diagrams/subagents-flow.svg)

### Откуда брать готовое — четыре маркетплейса

![subagents.cc — каталог Claude Code Agents с превью и копированием curl](/screens/marketplace-subagents-cc.png)

1. **[`subagents.cc`](https://subagents.cc/)** — Claude Code Agents, веб-каталог с превью и установкой через `Copy curl`. Удобный поиск по доменам (Engineering, Design, Data). Топовые: `frontend-developer`, `ui-designer`, `backend-architect`. Самый дружелюбный путь, если не любишь копаться в GitHub.

2. **`github.com/wshobson/agents`** — самый популярный собранный вручную набор (75+ агентов): `code-reviewer`, `debugger`, `architect`, `data-scientist`, узкоспециализированные агенты под Python/React/Rust.

3. **`github.com/VoltAgent/awesome-claude-code-subagents`** — большая коллекция, разложенная по доменам (devops, security, mobile, ML). Удобно, когда ищешь под конкретный сценарий.

4. **`docs.claude.com/en/docs/claude-code/sub-agents`** — официальный гайд от Anthropic. Здесь логика и команда `/agents`, через которую ставятся свои.

### Топ-3 универсальных суб-агента

- **`code-reviewer`** — смотрит на код «без эмоциональной привязки» («я только что это написал»). Возвращает список проблем — баги, плохие практики, риски. Основной Claude решает, что чинить.

- **`debugger`** — когда что-то падает, и ты не понимаешь почему. Суб-агент идёт по логам, изолирует причину, возвращает гипотезу + минимальный пример.

- **`general-purpose researcher`** (встроен в Claude Code) — длинные исследования, которые забили бы основной контекст. «Изучи 10 конкурентов и сравни» — улетает в суб-агента, возвращает таблицу.

### Главное про суб-агентов

То же правило, что и со skills/MCP: универсальных хватает на старте, дальше ты создаёшь своих через `/agents` под свои конкретные процессы. Команда `/agents` в Claude Code — главная точка входа: список встроенных, доступ к твоим, добавление новых.

### Паттерн «три роли» — для длинной задачи

Когда задача большая — не пытайся уложить её в один контекст. Разнеси на **три суб-агента с разными ролями**:

1. **Читатель** — изучает то, что уже есть (старый код, материалы, исследования). Возвращает короткое резюме «что было, как устроено».
2. **Исполнитель** — берёт резюме читателя плюс твой бриф, делает основную работу.
3. **Тестировщик / ревьюер** — проверяет результат исполнителя свежими глазами. Возвращает список багов или замечаний.

Каждый — со своим чистым контекстом. Твой основной чат — диспетчер: получает три коротких отчёта, решает, что дальше.

Бытовой пример: задача «переписать страницу о проекте по новому брифу».
- **Без ролей:** один длинный чат, в нём же читаем старый текст, в нём же пишем новый, в нём же пытаемся проверить себя. К концу контекст забит, качество плывёт.
- **С ролями:** читатель отдаёт «вот что было, вот ключевые мысли». Исполнитель пишет «вот мой вариант». Ревьюер находит «вот этот абзац противоречит брифу, вот тут потеряли цифру». Ты три раза прочитал короткий результат, а не следил за длинным разговором.

### Skill vs суб-агент vs новая вкладка

| Ситуация | Решение |
|---|---|
| Узкая подзадача внутри большой | Суб-агент |
| Параллельная работа над частями проекта | Несколько вкладок |
| Нужна «вторая голова» для критики | Суб-агент в роли ревьюера |
| Долгое исследование, забивающее контекст | Суб-агент-исследователь |
| Регулярно повторяющаяся узкая задача | Skill (не суб-агент) |

Skill — инструкция, которую читает один Claude. Суб-агент — отдельная сессия. Не путай.

## Лучшие практики по всем трём инструментам

**Skills**
- **`description` — главное, что ломается у новичков.** Без конкретных триггер-слов skill просто не подхватится автоматически — будет лежать, как будто его нет. Плохо: «помогает с интервью». Хорошо: «используй когда: "саммари интервью", "разбери интервью", "выводы по транскрипту"». Распространённая ошибка — описание написано «о чём skill», а не «по каким словам Claude его подхватит». Это то, чего не умеют 95% начинающих, и из-за чего они потом говорят «skills у меня не работают».
- Один skill — одна задача. Не делай универсальный «супер-помощник».
- Файл `SKILL.md` ≤ 100 строк. Длиннее — Claude дольше читает, ты дольше поддерживаешь.
- Не создавай skill для разовой задачи. Порог — 3 повтора в неделю.

**MCP**
- При подключении выдавай минимум прав. Лучше потом расширить, чем сужать.
- Никогда не подключай MCP к продовой БД. Только staging / read-only.
- Разделяй контуры: личный Notion и рабочий — разные коннекторы.
- На write-операциях («удали», «отправь», «создай») — обязательно `plan mode`.

**Суб-агенты**
- Запускай, когда задача требует **5+ чтений файлов** или **длинного исследования**. На простой задаче накладные расходы съедают пользу.
- Возвращай **короткое резюме**, не дамп. Если суб-агент возвращает 30 КБ текста — половина смысла потеряна, основной контекст всё равно забился.
- Один суб-агент — одна узкая задача. Не делай «универсального помощника по проекту».
- Для критики результата — отдельный суб-агент-ревьюер. Не проси основной чат «оцени, что ты только что написал» — это не работает.

## Как беречь контекст: тезисно

Контекст — это «оперативная память» сессии. Она конечная. Чем плотнее ты её сжигаешь — тем быстрее модель начинает забывать. Ниже — приёмы по убыванию эффекта.

1. **`/clear` между несвязанными задачами.** Закончил с одной фичей — очисти. Не превращай чат в мусорку, где живут вчерашний баг, позавчерашний дашборд и сегодняшний рефакторинг.
2. **`/compact` при заполнении 70–80%.** Сжимает историю, оставляя суть. Включай, как только видишь в `/context`, что осталось 30%.
3. **`/context`** — регулярная самопроверка. Запускай раз в час работы. Если сжигаешь контекст быстрее, чем ожидал — значит, что-то делаешь неэффективно.
4. **Суб-агенты — для тяжёлых чтений и исследований.** Не читай 20 файлов в основном чате. Делегируй.
5. **MCP вместо копипаста данных.** `Context7` для свежей документации SDK. `Playwright` для сбора данных со страниц. Не вставляй данные руками — пусть Claude сходит сам.
6. **Skills вместо повторного промпта.** Если уже два раза в этой сессии написал «сделай саммари по структуре X, Y, Z» — это уже skill, не промпт.
7. **CLAUDE.md + auto-memory вместо пересказа.** Каждое «у нас Next.js, мы не любим any, дедлайн 5 мая» — должно жить в файлах, а не в твоих сообщениях каждую сессию.
8. **Правильная модель.** Opus думает «громко» — расходует контекст быстрее. На рутинных задачах переключайся на Sonnet или Haiku через `/model`.
9. **Один проект — один CLAUDE.md, не один большой чат на всё.** Открыл папку проекта → новый чат с готовым контекстом из CLAUDE.md. Не возишь между проектами одну сессию.
10. **Не вставляй файлы целиком, если нужна одна функция.** Дай Claude grep/read — он подтянет только нужный кусок. Целый файл = весь файл в контексте, даже если нужно 5 строк.
